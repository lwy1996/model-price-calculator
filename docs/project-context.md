# 项目背景说明

## 1. 项目角色

`D:\php\wamp64\www\model-price-calculator` 是技能 `model-price-calculator` 的源开发目录，而不是最终使用时的技能投放目录。

这意味着：

- 用户平时真正调用 skill 时，读取的是技能使用目录中的文件，而不是本开发目录中的当前工作副本。
- 技能规则、提示词、数据结构、脚本逻辑的长期维护都应优先在本项目完成。
- 技能实际使用目录中的内容通常是由本项目经一键同步脚本或既有同步流程生成/覆盖的结果。
- 如果一个改动需要长期保留，默认应改源目录，而不是直接修改同步后的技能目录。
- 在本项目里进行技能维护、价格库录入、规则调整时，默认都只修改本开发目录；同步到技能使用目录由用户手动执行。

## 2. 为什么需要这份文件

这个项目同时承担几类职责：

- 技能主提示词与工作流维护
- 价格库与草稿数据维护
- 价格提取、计算、入库脚本维护
- 给最终技能目录提供同步来源

如果没有项目级说明，后续协作时很容易出现这些问题：

- 把“使用目录”误当成“源目录”
- 只改 `SKILL.md`，但忘了同步检查配套数据或脚本
- 新增规则时，文档、脚本、价格库口径不一致
- 在错误目录修修补补，导致后续一键同步把改动覆盖掉

## 3. 当前目录约定

按当前仓库结构，建议把各目录理解为：

- `SKILL.md`
  - 技能的主说明文件
  - 主要承载工作流、输入规则、输出规则、计算规则、图片识别规则等

- `assets/site-price-registry.json`
  - 站点价格正式库
  - 用于沉淀长期维护的站点价格数据

- `assets/site-price-drafts.json`
  - 站点价格草稿库
  - 用于暂存待确认、待整理或测试中的价格数据

- `scripts/`
  - 技能相关脚本目录
  - 包含价格计算、图片价格提取、站点价格草稿生成、价格入库、批量导入等脚本

- `references/`
  - 示例、参考资料、说明样例
  - 适合存放帮助理解技能输入输出形式的辅助材料

- `agents/`
  - 与代理/调用配置相关的文件

## 4. 维护原则

### 4.1 源目录优先

默认假设：

- 本项目是唯一应被长期维护的源头。
- 如果同步后的技能目录与本项目内容不同，应以本项目为准进行修正，再通过既有同步流程更新使用目录。

### 4.2 单一事实来源

涉及以下内容时，尽量保持单一事实来源，不要并行维护两套规则：

- 技能提示词规则
- 输入字段定义
- 输出文案模板
- 价格计算口径
- 站点价格数据结构

如果必须拆分，请在文档中明确“哪个文件是源头，哪个文件是派生物”。

### 4.3 修改时的联动意识

常见联动关系如下：

- 改 `SKILL.md` 中的输入/输出规则时，要检查脚本输出字段是否仍匹配。
- 改价格库结构时，要检查 `scripts/` 下读取与写入逻辑是否仍兼容。
- 改示例或参考文案时，要确认不会与当前技能主规则冲突。
- 改同步相关说明时，不要写死未经核实的脚本名、目标目录或覆盖策略。

## 5. 对协作代理的期望

在这个项目里工作时，优先遵循下面的判断顺序：

1. 先确认这次任务是在维护“源开发目录”，还是在讨论“最终技能使用效果”。
2. 如果任务发生在本项目上下文里，即使目标是“让 skill 以后这样工作”，默认也先改本项目，不直接改同步后的技能目录。
3. 若改动涉及规则、脚本、数据三者之一，要主动检查是否存在联动影响。
4. 若项目里缺少某项长期背景，应优先补充到 `docs/` 或 `AGENTS.md`，避免把关键信息只留在对话里。

## 6. 适合补充到这里的后续信息

后面如果你持续维护这个项目，建议把这些内容逐步补全到本文件或相邻文档：

- 实际同步脚本的位置与使用方式
- 同步目标目录的约定
- 价格库字段定义与状态流转规则
- 草稿数据转正式数据的操作流程
- 常见验证命令与无副作用检查方式
- 哪些文件允许直接编辑，哪些文件属于脚本生成产物

## 7. 当前约束

在尚未把同步流程文档化之前，保守约定如下：

- 可以维护本项目中的源文件。
- 不应凭猜测修改外部技能使用目录。
- 不应凭猜测触发覆盖式同步命令。
- 不应新增与现有规则平行、但缺乏归属说明的提示词文件或数据文件。
