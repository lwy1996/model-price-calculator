# 示例

## 单方案示例

输入：

```text
模型名称：gpt5.4
分组：Pro
输入价格：$2.5000 / 1M Tokens
补全价格：$15.0000 / 1M Tokens
缓存读取价格：$2.2500 / 1M Tokens
缓存创建价格：$2.5000 / 1M Tokens
倍率：1
充值比：29.99:1000
```

应重点得出：

- 输入美元每百万：`2.5000`
- 输出美元每百万：`15.0000`
- 缓存读取美元每百万：`2.2500`
- 缓存创建美元每百万：`2.5000`
- 输入人民币每百万：`2.5000 * 1 * 29.99 / 1000`
- 输出人民币每百万：`15.0000 * 1 * 29.99 / 1000`
- 综合基础价：`2.5 + 15 + 2.25 + 2.5 = 22.25`

```text
输入价格 ¥7.0000 / 1M Tokens
```

```json
{

  "cache_read_price": "¥0.7000 / 1M Tokens",
  "multiplier": 1,
  "recharge_ratio": "1:1"
}
```

再继续计算，不需要额外追问充值比。

## 中转站收录示例

输入：

```json
{
  "station": {
    "alias": "alpha",
    "name": "Alpha Gateway",
    "website": "https://alpha.example.com",
    "api_base_url": "https://alpha.example.com/v1"
  },
  "pricing": {
    "model_name": "gpt5.4",
    "group": "pro",
    "input_price": "$2.5 / 1M",
    "output_price": "$15 / 1M",
    "cache_read_price": "$0.25 / 1M"
  }
}
```

执行顺序：

1. `search` 检查是否已收录站点
2. `upsert` 写入或更新该站点的 `gpt5.4 + pro` 记录
3. `rank` 查看当前 `gpt5.4 + pro` 的性价比排序

## 中转站更新示例

如果用户说“更新 alpha 的 gpt5.4 pro 价格”，则：

1. 先用别名 `alpha` 检索
2. 命中后只更新同一个站点下的对应模型/分组记录
3. 保留其他模型或其他分组记录不变

## 继承默认值示例

如果站点 `ToioTo AI` 已经存在：

```text
模型：gpt-5.4
分组：default
倍率：0.1
```

此时用户只说：

```text
ToioTo AI
gpt-5.4
输入 3
输出 18
缓存读取 0.3
```

则应优先继承已有记录：
- 分组继续按 `default`
- 倍率继续按 `0.1`

而不是回退成：
- 分组 `default` 之外的新分组
- 倍率 `1`

如果站点本身已经记录过分组倍率表，例如：

```text
倍率：free分组0.1 plus分组0.15
```

即使某个模型是第一次录入，只要用户明确写了分组是 `free` 或 `plus`，也应优先继承该站点对应分组倍率，而不是回退到 `1`。

## 批量分组范围示例

输入：

```text
站点名称：小鸡农场
官网：https://api.68886868.xyz
API：https://api.68886868.xyz
倍率：free分组0.1 plus分组0.15
以下都是free分组下倍率后的价格：
gpt-5.4
输入价格 0.2500 / 1M Tokens
补全价格 1.5000 / 1M Tokens
缓存读取价格 0.0250 / 1M Tokens
```

应按以下规则处理：

- 只入库 `free` 分组，不要自动复制出 `plus`
- 同时把站点级倍率表保存下来：`free=0.1`、`plus=0.15`
- 因为文本说明“倍率后的价格”，入库前先反推原始价：
  - 输入：`2.5`
  - 输出：`15`
  - 缓存读：`0.25`

如果用户明确希望“其他分组也一起记录”，则应继续基于反推后的原始价派生其他分组。例如：

- `free=0.1`
- `plus=0.15`
- 已知 `free` 的倍率后价格是：
  - 输入：`0.25`
  - 输出：`1.5`
  - 缓存读：`0.025`

则应先反推原始价：

- 输入：`2.5`
- 输出：`15`
- 缓存读：`0.25`

再生成 `plus` 记录：

- 输入：`0.375/M`
- 输出：`2.25/M`
- 缓存读：`0.0375/M`

## 同站不同模型不同倍率表示例

输入：

```text
站点名称：测试站
官网：https://example.com
API：https://example.com/v1

gpt-5.4
倍率：free分组0.1 plus分组0.2
以下都是free分组下倍率后的价格：
输入 $0.25/M
输出 $1.5/M
缓存读取 $0.025/M

gpt-5.5
倍率：free分组0.3 plus分组0.45
以下都是free分组下倍率后的价格：
输入 $1.5/M
输出 $9/M
缓存读取 $0.15/M
```

应按模型分别处理，而不是套用同一套倍率：

- `gpt-5.4` 反推原价为 `2.5 / 15 / 0.25`，再派生 `free + plus`
- `gpt-5.5` 反推原价为 `5 / 30 / 0.5`，再派生 `free + plus`

## 一键入库示例

输入：

```text
站点别名：gamma
官网：https://gamma.example.com
API：https://gamma.example.com/v1

输入价格 $2.8 / 1M
补全价格 $16.8 / 1M
缓存读取价格 $0.28 / 1M
```

做法：

1. 把站点字段作为 `station`
2. 把原始价格文本交给 `scripts/ingest_site_price.py`
3. 由脚本自动提取价格、写库并返回最新排序

## 引导式收录示例

用户只说：

```text
帮我记一下一个中转站
```

此时先问：

```text
先给我一个能识别这个站的信息即可：站点别名、官网地址、或 API 地址，三选一就行。
```

如果用户回答：

```text
别名 alpha
```

再继续问：

```text
这个站你要记录哪个模型？如果有分组也一起告诉我；没有分组我可以先按默认分组记。
```

如果用户再回答：

```text
gpt5.4 pro，输入2.4，输出14.5，缓存读取0.24
```

此时再入库。

## 草稿补录示例

第一轮用户只说：

```text
帮我记一个站，别名叫 delta
```

先 merge 到草稿，草稿状态应提示还缺：
- 模型名称
- 输入价格
- 输出价格

第二轮用户说：

```text
模型是 gpt5.4，分组 pro
```

再次 merge 后，草稿状态应提示还缺：
- 输入价格
- 输出价格

第三轮用户说：

```text
输入 2.6，输出 15.6，缓存读取 0.26
```

再次 merge 后，草稿应变为可提交状态，然后执行 commit 正式入库。

## 批量录入示例

输入：

```text
站点名称：Xybbz
官网：https://sub2api.xybbz.xyz
API：https://sub2api.xybbz.xyz/v1
倍率：free分组0.07 plus分组0.15 Pro分组0.25
gpt-5.4价格：
输入 $2.5000/M
输出 $15.0000/M
备注：v2ex站推广的 已添加QQ群
```

应自动拆成：
- `gpt-5.4 / free / 0.07`
- `gpt-5.4 / plus / 0.15`
- `gpt-5.4 / pro / 0.25`

如果同一段里还有：

```text
gpt-5.5价格：
输入 $5.0000/M
输出 $30.0000/M
```

则继续自动补成：
- `gpt-5.5 / free / 0.07`
- `gpt-5.5 / plus / 0.15`
- `gpt-5.5 / pro / 0.25`
